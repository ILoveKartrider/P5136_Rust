# P5136 Rust 서버

[한국어](README.md) | [English](README.en.md) | [简体中文](README.zh-CN.md) | [변경 기록](CHANGELOG.md)

번역이 어색하거나 잘못된 부분을 발견하면 [이슈](https://github.com/ILoveKartrider/P5136_Rust/issues)를 열거나 PR을 보내 주세요.

한국 카트라이더 P5136 클라이언트를 위한 독립 Rust 서버·접속기입니다. 원본 C# 프로젝트는 프로토콜 동작을 확인하는 읽기 전용 참고 자료로만 사용하며 이 저장소에 포함하지 않습니다.

이 프로젝트는 아직 모든 상용 서비스 기능을 재현한 완성 서버가 아닙니다. 현재 목표는 친구들과 같은 LAN에서 방 생성·입장, 게임 시작, 주행, 결과·시상식, 다시 방으로 돌아오는 멀티플레이 사이클을 안정적으로 지원하는 것입니다. Lucci, 보너스 아이템, 팀 플래그와 일부 이벤트·소셜·상점 기능은 범위 밖이거나 제한적으로 응답합니다.

사용자 안내, 포팅 현황, 클라이언트 FSM, 패킷·아이템·AI 정적 분석 문서의 역할과 최신 기준은 [전체 문서 안내](DOCUMENTATION.md)에 정리되어 있습니다.

## 빠른 시작

Rust 1.94 이상에서 다음 명령으로 릴리스 빌드를 만듭니다.

```powershell
cargo build --release -p p5136-cli
```

Windows Server 2012 x64용 레거시 호환 빌드는 원본 소스를 수정하지 않고
별도 타깃과 정적 CRT로 만든다. 자세한 절차와 검증 범위는
[Windows Server 2012 호환 빌드 메모](WINDOWS_SERVER_2012.md)를 참고한다.

현재 저장소의 고정 빌드 경로는 다음과 같습니다.

```text
target/p5136-finish-kart-abilities/release/p5136.exe
```

`p5136.exe`를 인자 없이 실행하면 GUI가 열립니다. 우측 상단에서 한국어, English, 简体中文을 선택할 수 있으며 선택한 언어는 다음 실행에도 유지됩니다. 하나의 실행 파일 안에 서버와 접속기가 들어 있으며 GUI 탭으로 구분됩니다.

1. 서버 탭의 필수 항목인 `클라이언트 또는 Profile 경로`에 P5136 클라이언트 루트를 지정합니다. 비워 두면 서버가 시작되지 않습니다. 예: `C:\Games\KartRider_5136`.
2. 다른 PC가 접속한다면 `내 LAN IPv4로 자동 설정`을 누릅니다. 여러 어댑터가 있으면 목록에서 실제 LAN 주소를 선택합니다.
3. 새 원격 닉네임으로 처음 접속한다면 `LAN의 새 닉네임 허용`을 체크합니다.
4. `서버 시작`을 누릅니다.
5. 접속기 탭에 게임 디렉터리, 닉네임, 서버 IPv4를 넣고 `클라이언트 준비 및 실행`을 누릅니다.
6. XUN 카트를 사용할 때는 클라이언트가 실행된 뒤 옆의 `XUN DLL 연결`을 누르고 UAC 요청을 승인합니다. 기본값은 접속기와 같은 폴더의 `p5136-xun-attach.exe`와 `p5136-xun.dll`이며, 접속기 탭에서 두 파일을 각각 직접 선택할 수도 있습니다. DLL 로그 기록은 같은 화면의 체크박스로 켜고 끕니다.

접속기는 원본 파일의 불변 백업과 프로세스 잠금을 사용해 PIN/XML을 준비한 뒤 Windows UAC, Wine, CrossOver 또는 macOS Sikarugir wrapper로 클라이언트를 실행합니다. Sikarugir의 Wine prefix와 wrapper를 수동으로 준비하는 방법은 [macOS Sikarugir walkthrough](MACOS_SIKARUGIR.md)를 참고하세요.

## 클라이언트 데이터 자동 탐지

클라이언트 루트, `Profile` 폴더 또는 `Data` 폴더를 지정할 수 있습니다. 서버는 `Data` 폴더를 자동으로 찾고 다음 원본을 제한형·읽기 전용으로 직접 해석합니다. C# 서버가 생성하던 `Profile/KartCatalog.xml`은 필요하지 않습니다.

- `Data/kart.rho`와 RHO5 overlay: 카트 이름과 주행 물리
- RHO5 `zeta_/kr/shop/data/item.kml`: 인벤토리 카탈로그
- `Data/item.rho`: 카트별 아이템 변환 규칙과 개인전·팀전 확률표
- `Data/track_common.rho`: 모드·랜덤 selector별 트랙 목록
- 그 밖의 RHO5 데이터: 엠블럼 등 지원 데이터

아이템 확률표의 기본 모드는 `서버 시작 시 자동 적용`입니다. 시작 버튼을 누르면 실제 `item.rho`를 먼저 읽어 개인전·팀전 항목 수와 적용 경로를 GUI에 표시하고, 그때 읽은 정확한 스냅샷을 해당 서버 실행에 넘깁니다. 로드 실패 시 서버를 시작하지 않습니다. `불러와 고정`이나 XML을 사용한 경우에만 이후 클라이언트 경로 변경과 무관한 수동 값이 됩니다.

세베크 V1 같은 카트의 아이템 변환도 `item.rho`의 `transformByKart`를 직접 읽어 서버가 최종 획득 아이템을 결정합니다. 예를 들어 세베크 V1의 황금 실드는 클라이언트가 자동 변환하는 것이 아니라 서버 규칙으로 처리됩니다. 기본 및 한국 `animalBooster` 테이블도 별도로 병합하므로 파라오 HT·바스테트 X 같은 카트는 아이템 31을 받고, 클라이언트가 카트별 황금 부스터를 표시합니다. 황금 실드와 황금 부스터는 서로 독립된 효과입니다. 서버 시작 시 만든 카탈로그는 불변 메모리 스냅샷이며 RHO나 클라이언트 폴더를 수정하지 않습니다.

## 닉네임별 카트 인벤토리

GUI의 `닉네임별 인벤토리 편집`을 펼치면 강화 상태가 다른 동일 카트를 여러 대 소유하도록 추가할 수 있습니다. 서버 실행 중에도 같은 프로필 작업 큐를 통해 원자적으로 저장되며, 이미 접속한 클라이언트에는 재접속 후 반영됩니다.

1. 서버의 `클라이언트 또는 Profile 경로`와 `프로필 저장 경로`를 먼저 지정합니다.
2. `카트 목록 불러오기`를 눌러 클라이언트 RHO의 실제 이름과 ID를 읽습니다.
3. 인벤토리를 편집할 닉네임을 입력합니다. `접속기 닉네임 사용`으로 현재 접속기 값을 복사할 수도 있습니다.
4. `기간테스 V1`, 공백을 뺀 `기간테스v1`, 또는 숫자 ID `1410`을 입력하고 후보 드롭다운에서 카트를 선택합니다.
5. `선택 카트 추가`를 누릅니다. 같은 카트를 다시 누르면 다음 고유 serial로 한 대가 더 추가됩니다.

서버는 이름, `BodyParam`, 실제 `model.1s`가 모두 해석되고 테스트/더미/NPC 흔적이 없는 카트만 기본 serial 1로 자동 제공합니다. 기본 P5136 데이터에서는 카트 1,296개 중 1,284개가 이 검사를 통과하며, 나머지 12개(ID `199, 312, 323, 352, 657, 658, 659, 744, 745, 746, 814, 886`)는 인벤토리 스크롤 크래시를 피하기 위해 자동 지급과 이름 검색에서 격리됩니다. 실제 클라이언트에서 지원됨을 직접 확인했다면 검색란에 정확한 숫자 ID를 입력해 `[수동 확인]` 후보를 선택할 수 있습니다. 이 예외는 기본 serial 1을 다시 열지 않고 해당 닉네임에 serial 2 이상 소유분만 추가합니다.

추가 소유분은 닉네임별 프로필의 `GrantedKarts`에 원자적 저장되며, 장착·플로터·플랜트·강화·파츠 데이터가 사용하는 `(kart_id, serial)` 키와 같으므로 각 복사본을 서로 다르게 강화할 수 있습니다. 할당기는 현재 grant뿐 아니라 남아 있는 `TuneData.json`/`PlantData.json`/`LevelData.json`/`PartsData.json` serial도 예약하므로 과거 강화 상태를 새 복사본이 잘못 물려받지 않습니다. 프로필이 아직 없는 닉네임은 첫 추가 시 생성됩니다. 이미 접속한 클라이언트에는 재접속 후 반영됩니다.

옛날 엔진 카트 강화는 지인 서버용 간소화 정책을 사용합니다. 대상 카트와 재료 카트의 소유 여부는 검사하지만 재료 카트와 재화는 소모하지 않고 성공 확률은 항상 100%입니다. 강화 단계·남은 포인트·네 슬롯 배분·특수 효과는 닉네임별 `LevelData.json`에 저장되며, 재접속 인벤토리와 실제 경기 물리에 다시 반영됩니다. 각 슬롯은 0~10, 전체 배분은 35포인트로 제한되며 클라이언트가 보내는 음수/양수 변화량으로 범위 안에서 포인트를 재배분할 수 있습니다.

플로터도 클라이언트의 기존 소켓 생성·활성 키트·보호 스패너·초기화 UI를 그대로 사용합니다. 소모품은 차감하지 않지만 대상 카트 소유권, 카트 타입, 슬롯 상태는 검사하고 결과를 닉네임별 `TuneData.json`에 원자적으로 저장합니다. Black 계열 활성 키트가 만드는 `603/703/903`은 각각 출발 부스터 시간 `+800`, 변신 가속 `+0.018`, 드리프트 탈출력 `+210`으로 실제 경기 물리에 합성됩니다. 일반 스피드 플로터 `103`~`903`도 원본 C# 수치대로 반영됩니다. 아이템 플로터의 20개 의미는 한국 P5136 RHO5의 `zeta_/kr/enchant/desc.xml`을 기준으로 해석합니다. 그중 아이템 상자에서 결정되는 실드→슈퍼 실드, 물폭탄→독성/얼음 물폭탄, 미사일→황금 미사일, 부스터→사이렌/슈퍼 실드, 바나나→물지뢰 변환은 서버 지급 경로에 반영됩니다. 각 확률은 `enchant.xml`의 코드별 원본 값(예: `10503` 15%, `11103` 40%, `11403` 25%, `11803` 30%)을 사용하며 대체 사용 효과는 100%입니다. 반면 `firing2Gain` 사용 보상 78개와 `fired2Gain` 피격 보상 150개는 클라이언트가 직접 확률 판정·지급합니다. 서버는 해당 GameSlot type 10/11을 원본 그대로 relay하며 중복 보상을 합성하지 않습니다.

GUI에서 카트를 지급할 때 `333 프리셋`을 그대로 사용할 수도 있고, 세 플로터 슬롯을 세로로 배치된 드롭다운에서 각각 지정할 수도 있습니다. 검증된 스피드 코드 27개와 RHO로 의미를 확인한 아이템 효과 코드 20개를 모두 실제 한국어 효과명으로 표시합니다. 같은 스피드 효과 계열이나 동일 아이템 코드를 중복 지정한 조합은 카트를 만들기 전에 거부하며, `5강 적용`은 플로터 선택과 독립적으로 함께 사용할 수 있습니다.

기본 카트 인벤토리는 역사적인 내부명에 `dummyBox`가 들어가지만 실제 한국 리소스가 완전한 카트라넥/카트라넥 X만 P5136 예외로 포함합니다. 박스터 HT-S/HT-B/HT LE는 공유·불완전 모델 레이아웃이 실제 클라이언트에서 더미처럼 동작하므로 다시 격리합니다. 그 밖에 한국용 BodyParam이 없는 4대(스노우 모빌 PRO, 꽃돼지 SR, 루돌프 썰매 PRO, 8주년 기념 몬스터 HT+)와 명시적인 더미·테스트 5대도 계속 제외됩니다.

편집 중에는 서버와 같은 프로필 루트 잠금을 잠깐 획득하고 저장소 고유 ID도 재검증합니다. 이 GUI뿐 아니라 다른 프로세스의 서버가 실행 중이어도 추가를 거부하므로 서버를 먼저 종료해야 합니다. 카트 목록을 읽은 뒤 클라이언트 경로를 바꾸면 목록과 선택은 무효화되며, 추가 직전에도 현재 `Data` 실제 경로가 같은지 다시 대조합니다.

현재 편집기는 의도적으로 중복 카트 추가만 지원합니다. 일반 카탈로그 아이템은 서버가 이미 기본 인벤토리에 제공하므로, 수량형 아이템 구매·지급은 가격·재화·만료·재시도 정책을 갖춘 별도 economy 기능으로 남겨 두었습니다.

## 랜덤 트랙

서버는 클라이언트의 RHO 1.0 `track_common.rho`를 제한형·읽기 전용으로 해석합니다. 스피드/아이템 모드와 selector `0, 1, 3~8, 23, 30, 33, 40`에 맞는 실제 후보 풀에서 프로세스 난수로 선택하며, 같은 방에서는 현재 풀을 소진하기 전에 같은 트랙을 다시 고르지 않습니다. AI가 있으면 `basicAi` 트랙을 우선하고 목록이 비면 원래 풀로 되돌아갑니다.

GUI의 `랜덤 트랙 설정`에서 클라이언트 목록을 미리 읽으면 풀별 후보가 체크박스로 표시됩니다. 개별 맵 선택과 `모두 선택`, `모두 해제`, `클라이언트 기본값` 복원을 지원합니다. 서버 실행 중에도 `실행 중 서버에 적용`으로 풀 전체를 원자적으로 교체할 수 있으며, 이미 로딩·주행 중인 경기는 유지하고 다음 경기 시작부터 새 목록을 사용합니다. 수동 설정이 없는 풀은 클라이언트 기본값을 그대로 사용하며, 빈 사용자 지정 목록은 붉은 경고를 표시하고 적용 및 서버 시작 전에 거부합니다. 수동 설정은 원본 ID를 검증해야 하므로 클라이언트 `Data` 경로 없이 사용할 수 없으며, 경로가 사라지면 오류로 중단합니다.

## AI 난이도 정적 분석

일반 방의 AI 추가/삭제 요청에는 난이도 값이 없습니다. 실제 AI 동작 파라미터는 경기 시작의 `GrCommandStartPacket`에 AI 한 명당 암호화 float 6개로 들어갑니다. 서버 관리의 `AI 주행 파라미터`에서 스피드전과 아이템전 값을 따로 설정할 수 있으며 기본값은 각각 `[0.7, 2400, 2950, 1.5, 1000, 1500]`, `[0.6, 2400, 2950, 1.5, 1000, 1500]`입니다. 설정은 GUI에 저장되고 서버를 다시 시작한 뒤 다음 경기부터 적용됩니다. 과거 C# GUI의 쉬움·어려움·지옥은 이 여섯 값을 모드별 범위에서 무작위 생성하는 프리셋이었고, 클라이언트가 보내는 원래 enum은 아닙니다.

정적 소비 경로를 추가로 복원한 결과, 앞의 두 값은 곱해져 AI 기본 목표 속도를 만들고, 세 번째 값은 부스터 유지 시간(ms), 네 번째 값은 부스터 가속 배율로 쓰입니다. 다섯 번째와 여섯 번째 값은 P5136 코덱을 통과하지만 `GoBasicAiKart`에서는 읽지 않는 예약 필드입니다. 정확한 수식과 클라이언트 `basicAI.xml`의 보완 파라미터는 [AI 난이도 감사 문서](AI_DIFFICULTY_AUDIT.md)에 기록했습니다. 듀얼 미션 난이도 패킷과 배틀 AI 경로는 일반 방 AI와 별개입니다.

## 방 제목 S0~S8 물리

방 제목에 독립된 `S0`~`S8` 토큰을 넣으면 C# 서버와 같은 현대 물리 프리셋을 경기 시작 시 적용합니다.

서버 관리의 `타임어택 물리 프리셋`에서는 `기본 설정 (클라이언트 선택)` 또는 S0~S8을 선택할 수 있습니다. 기본 설정은 기존처럼 클라이언트 요청 등급을 유지하고, S0~S8 선택은 모든 타임어택 시작 응답의 235바이트 물리 블록을 해당 등급으로 덮어씁니다. 서버를 다시 시작한 뒤 적용됩니다.

```text
[S0] 초보방
친선 S2
S4 무한부스터
```

토큰은 대소문자를 구분하지 않으며 ASCII 영숫자 경계를 따릅니다. 따라서 `TESTS1ROOM`이나 `S10`은 물리 토큰으로 인식하지 않습니다. 방장이 대기실에서 방 제목을 바꾸면 제목과 비밀번호가 모든 참가자에게 즉시 갱신되고, 새 제목의 S0~S8 토큰은 다음 경기 시작 물리에 적용됩니다. 원본 C#과 같이 이미 생성된 방의 채널/세션 speed byte는 제목 변경으로 바뀌지 않습니다. 토큰이 없으면 일반 스피드와 아이템 채널 모두 P5136 `channel.xml`의 통합 S7을 사용하고, 개인/팀 무한부스터 채널은 원본 일반 무한부스터인 S4를 사용합니다. 아이템 개인/팀은 speed byte가 아니라 game type 2/4로 각 아이템 물리 행을 선택합니다. S6는 이벤트용 특수 무한부스터이며, S8은 클라이언트에 `통합속도` 표시 키와 물리 슬롯이 남아 있지만 활성 기본 채널에는 연결되지 않은 수동 프리셋입니다. 각 플레이어의 카트·펫·장비와 이 기본값을 합성한 235바이트 경기 시작 물리 블록이 전송됩니다.

## 계정 역할: 옵저버와 익명 리그

접속기에서 `옵저버 모드 (pmap 718)`를 선택하면 launcher 프로필이 옵저버 방장 역할을 요청하고, 서버가 해당 닉네임의 `pmap`을 원자적으로 저장합니다. 체크를 해제하고 다시 접속하면 일반 계정 값 `0`으로 복귀합니다. C#과 같이 pmap 718 옵저버는 8~15번 옵저버 슬롯에 들어가면서 실제 `RoomMaster`가 되며, 일반 라이더가 입장한 뒤에도 개인전·팀전 맵 변경과 경기 시작 권한을 유지합니다. pmap 590 일반 옵저버에는 이 자동 권한을 주지 않습니다.

방 채팅도 C#과 동일하게 옵저버 ID 8~15를 넣은 `GrRiderEchoPacket`을 발신자를 제외한 방 구성원 전원에게 보냅니다. Rust 회귀 테스트는 일반 라이더 두 명에게 같은 프레임이 전달됨을 검증합니다. 다만 일반 클라이언트 화면에 표시되는지에 대한 실기 확인은 옵저버와 일반 계정이 동시에 접속한 캡처가 필요합니다.

`익명 리그 모드 (pmap 1798)` 체크박스는 옵저버 모드와 배타적으로 launcher 프로필에 1798을 기록합니다. 정적 분석상 1798은 `0x400|0x200|0x100|0x4|0x2`이며, 확인된 리그 준비 경로에서 상대 캐릭터·색상·장비를 공통 프리셋으로 바꿉니다. 그러나 닉네임 문자열 자체를 바꾸는 클라이언트 분기는 확인되지 않았으므로 현재 서버는 이름을 익명화하지 않습니다. 1798의 추가 비트는 다른 UI에도 영향을 줄 수 있어 단순히 1068의 별칭으로 취급하지 않습니다. 체크를 해제하고 다시 접속하면 pmap 0이 저장됩니다.

## 차단·숨김 특수 트랙

접속기의 `차단·숨김 특수 트랙 표시 (실험적)` 체크박스는 P5136에 실제 트랙 RHO와 일반 `gameType` 정의가 모두 남아 있는 항목만 복원합니다. 현재 범위는 TF 3종(오토봇 기지, 갈바트론의 지구 습격, 사이버트론 행성의 비밀)과 안전 판정된 개별 차단 트랙 6종입니다. 일반 트랙 정의가 없는 카멜롯·올림포스·코리아·마비노기·메이플 `S` 스테이지는 선택 UI 정지·충돌 위험 때문에 제외합니다.

접속기는 원본 `track_common.rho`나 `aaa.pk`를 다시 쓰지 않습니다. 원래 비어 있는 `DataPack1_00014.rho5`를 최초 1회 `DataPack1_00014.rho5.pristine.bak`으로 보존하고, 한국어 트랙 로케일 한 파일만 담은 오버레이로 교체합니다. 13번 슬롯에 실험적 I/R 트랙 가져오기 카탈로그가 있으면 그 로케일을 기초로 패치하므로 가져온 트랙 행도 유지됩니다. 체크를 해제하고 다시 실행하면 최초 원본 슬롯을 복원합니다. `xyy`(시양양/喜羊羊)는 정의와 선택 이미지가 남아 있지만 실제 트랙 RHO가 3개 중 하나뿐이고 전용 BGM도 없으므로 이 안전 옵션에 포함하지 않습니다.

## 외부 클라이언트 트랙 가져오기

GUI의 `트랙 가져오기` 탭은 다른 한국/중국 클라이언트의 `Data` 폴더에서 RHO/RHO5를 직접 인덱싱하고, 사용 가능한 I/R 트랙을 검색·다중 선택해 현재 P5136의 완전한 `DataRaw`에 추가합니다. 검색·의존성 분석·쓰기·설치 단계와 파일 진행률을 프로그레스 바로 표시합니다. 트랙 파일, AI 경로, 썸네일, 테마, 트랙 로컬·공통·교차 테마 재질, 위치 환경음, 테마 BGM을 함께 감사합니다. P5136 실행 파일은 테마 enum을 34개로 고정하므로 BML에 새 행만 넣어서는 새 테마가 표시되지 않습니다. 현재 검증된 `fengshen` 가져오기는 제거된 XYY의 네이티브 슬롯 17을 내부 분류용으로 재사용하고, 실제 `fengshen_*` 트랙 ID·리소스·BGM 경로는 유지합니다. 구형 클라이언트의 별도 재질 테마 마스크를 채우기 위해 `texTheme=xyy`를 명시하며, `abyss|sword` 같은 기존 교차 테마는 `xyy|abyss|sword`로 보존합니다. 이름만 저장된 재질은 `theme/xyy`에서 조회하므로 `theme/fengshen` 리소스 전체도 XYY 런타임 네임스페이스에 비파괴적으로 미러링합니다. 이 슬롯은 기본 콘텐츠 설정에서도 누락되어 있으므로 가져오기는 `zeta_/kr/content/config.xml`의 `themeXyy`를 활성·표시 상태로 함께 등록합니다. 이미 설치된 트랙도 다시 선택해 누락 리소스와 테마 카탈로그/호환 속성을 복구할 수 있습니다. 다른 신규 테마는 검증된 슬롯 또는 클라이언트 패치가 마련되기 전까지 거부합니다. 같은 경로의 기존 파일이 다르면 덮어쓰지 않고 보고서에 충돌로 남기며, 작업물과 최초 카탈로그 백업은 게임 폴더의 `.p5136-track-import`에 저장합니다. 데이터 의존성이 모두 확인되어도 새 네이티브 gimmick/shader는 별도 호환성 검토가 필요합니다.

## 외부 클라이언트 자산 가져오기

GUI의 `자산 가져오기` 탭은 최신 중국 클라이언트의 `Data`를 인덱싱합니다. 안쪽의 `카트`, `캐릭터`, `펫`, `플라잉펫` 탭에서 정적 감사를 통과한 항목을 검색·다중 선택할 수 있고, `설치되지 않음만` 필터로 현재 `DataRaw`에 없는 항목만 볼 수 있습니다. 감사 집합은 일반 카트 57종, 복원된 `defaultExceedType`이 1~4인 XUN 시험 카트 100종, 캐릭터 73종, 펫 24종, 플라잉펫 47종입니다. P5136에 없는 새 아이템 결과를 요구하는 일반 카트 6종은 선택할 수 없으므로 현재 일반 카트 51종과 XUN 시험 카트 100종을 가져올 수 있습니다. 타입 5 이상의 별도 스킬 상태 머신을 쓰는 XUN 카트는 아직 표시하지 않습니다.

선택 항목은 가져오기 직전에 의존성 폐쇄와 SHA-256을 다시 검사합니다. 리소스는 완전한 `DataRaw`에 가산 설치하고, 기존 동일 경로 파일의 바이트가 다르면 덮어쓰지 않고 중단합니다. ASCII 코드명을 표시 이름으로 사용하고 나머지 비 ASCII 카탈로그 문자열은 안정적인 해시로 바꿉니다. `itemTable`, 한국 상점, 네 개의 카트 아이템 능력표는 병합하며, 플라잉펫의 중국 지역 파라미터는 한국 클라이언트가 읽을 `param@kr.bml` 별칭도 생성합니다. XUN 카탈로그의 미지원 세대 표기 `grade=13 / engineGrade=9`는 5136 정보창이 아는 V1 분류값 `12 / 8`로만 변환하고 실제 BodyParam/KartSpec 물리는 보존합니다. 서버는 감사된 카트·캐릭터 ID와 대응 `DataRaw` 모델이 모두 있을 때만 새 항목을 자동 지급합니다. XUN 카트는 정확한 빌드용 XUN 사이드카가 필요합니다. 사이드카는 lifecycle/XUN 상태, 여섯 개의 스피드전 물리 소비식, 독립적인 연속형 부능효과 게이지, 최신 카트·기본 파츠 표시값 변환을 연결합니다. 부능효과는 일반 Exceed와 별도 상태·UI·이펙트 경로입니다. 가져오기는 `defaultExceedType`에서 P5136의 `ExceedWaveType`을 복원해 일반 Exceed 효과를 유지하고, 사이드카는 별도의 렌더 객체에 가져온 `effect/charger/카트바디차저발동` 장면을 연결해 부능효과 aura를 시작·정지합니다. 흑기사 XUN은 최신 클라이언트와 같은 변환으로 `드리프트 1158 / 가속력 1159 / 코너링 1050 / 부스터 시간 1054`를 표시합니다. 이 구현은 `GoPlayKart` 크기를 늘리거나 Exceed 효과를 aura 대신 사용하지 않습니다. 정확한 `KartSpec.defaultExceedType=1` 아이템형 카트에는 서버가 개인전 아이템 확률표에서 시작 아이템을 선택하고 해당 카트의 일반 아이템 변환 규칙을 적용합니다. 서버가 시작 때 읽는 `DataPack1_00000.rho5`와 `DataPack4_00002.rho5`는 최초 원본을 `.pristine.bak`으로 한 번만 보존한 뒤 갱신합니다. 작업물·보고서·DataRaw 카탈로그 백업은 `.p5136-asset-import`에 저장되고, 성공하면 접속기의 전체 DataRaw 옵션이 자동으로 켜집니다. 적용 후 서버와 클라이언트를 다시 시작해야 합니다. 새 플라잉펫 ID의 서버 물리/특수효과는 기존 P5136 하드코딩 표에 없는 경우 별도 구현이 필요하므로, 이번 감사 결과는 표시·장착에 필요한 자산/카탈로그 호환성을 뜻합니다.

## 팀 배치와 다음 경기 출발 순서

팀전 방에 새 레이서가 들어오면 현재 인원이 적은 팀에 자동 배치됩니다. 인원이 같으면 블루를 먼저 선택하므로 최초 입장 순서는 블루, 레드, 블루, 레드가 됩니다. 팀별 물리 슬롯도 블루 0~3, 레드 4~7 범위를 유지하며 AI도 팀 인원 계산에 포함됩니다.

경기 정산이 끝나면 서버가 확정한 전체 순서(DNF 포함)를 대기실의 각 `RoomPlayer.ranking`에 저장합니다. 다음 경기의 `GrCommandStart`가 같은 값을 직렬화하므로 전 경기 순서가 다음 출발 그리드 입력으로 이어집니다. 중간 퇴장자가 있으면 상대적 결승 순서를 유지한 채 남은 참가자를 0부터 다시 연속 배치해 빈 출발 위치를 만들지 않습니다.

대기실로 복귀할 때 방장도 직전 경기 결과로 다시 선정합니다. 개인전은 남아 있는 인간 레이서 중 가장 높은 순위가, 팀전은 서버가 확정한 승리팀 안에서 가장 높은 순위가 다음 방장이 됩니다. AI·관전자·이미 퇴장한 레이서는 방장 후보에서 제외됩니다.

## LAN 주소와 도메인

`바인드 주소`는 서버가 실제로 포트를 열 로컬 인터페이스이고, `클라이언트에 알릴 IPv4`는 로그인·채널 패킷에 넣을 주소입니다. LAN 자동 설정 버튼은 루프백·링크 로컬 주소를 제외하고 물리 어댑터를 가상 어댑터보다 먼저, 그 안에서는 사설 IPv4를 우선합니다. Wi-Fi, Ethernet, WSL, VMware, VPN, Tailscale 등이 함께 보이면 실제 클라이언트와 같은 네트워크의 주소를 직접 선택하세요. 광고 주소의 `0.0.0.0`, 멀티캐스트, 브로드캐스트는 시작 전에 거부합니다.

현재 bind, advertised, 접속기 서버 주소는 IP 리터럴만 받습니다. 특히 advertised 주소는 P5136 패킷에 IPv4 4바이트로 직렬화되므로 도메인을 그대로 넣을 수 없습니다. 도메인을 쓰려면 실행 전에 A 레코드를 조회해 하나의 IPv4로 고정해야 하며, DNS 변경이 실행 중 서버 상태와 어긋날 수 있어 GUI 입력으로 지원하지 않습니다.

GUI는 서버·접속기 탭의 입력 설정을 운영체제별 앱 설정 저장소에 기록하고 다음 실행에 복원합니다. 여기에는 IP·포트·클라이언트/프로필 경로·닉네임·실행 방식·Wine/CrossOver/Sikarugir 값·고급 제한값·로그 파일 저장 체크박스·편집한 아이템 확률표·랜덤 트랙 선택이 포함됩니다. 실행 중에도 랜덤 트랙 적용과 닉네임별 카트 지급을 사용할 수 있습니다. 카트 지급은 활성 서버의 프로필 큐와 동일한 닉네임 lane에서 원자적으로 저장되며, 이미 접속한 클라이언트에는 재접속 후 표시됩니다. 실행 중/정지 상태, 로그 경로, 불러온 카탈로그, 검색 결과처럼 다시 계산해야 하는 일시 데이터는 저장하지 않습니다.

GUI 하단에는 현재 실행 중인 바이너리의 Cargo 패키지 버전이 항상 표시됩니다.

Windows에서는 맑은 고딕·Microsoft YaHei·SimSun, macOS에서는 Apple SD Gothic Neo·PingFang·AppleGothic, Linux에서는 Noto Sans CJK·나눔고딕 계열을 순서대로 찾아 한국어·영어·중국어 간체 GUI 글꼴로 사용합니다. 해당 글꼴이 없으면 설치 안내를 로그에 남깁니다.

기준 포트가 `39311`이면 다음 포트를 사용합니다.

| 용도 | 프로토콜 | 포트 |
|---|---:|---:|
| 게임 | UDP | 39311 |
| 로그인 | TCP | 39312 |
| P2P/relay | UDP | 39312 |
| 메신저 | TCP | 39313 |
| XUN 보조 채널 | TCP | 39314 |

XUN 보조 채널은 순정 게임 패킷과 분리되어 있으며, 선택적 XUN DLL의
카트별 물리 프로필에만 사용됩니다.

두 PC에서 테스트할 때 서버 PC 방화벽에 위 TCP/UDP 포트를 허용해야 합니다.

## 명령줄 실행

GUI 없이 서버만 실행할 수 있습니다.

```powershell
p5136.exe server `
  --bind 192.168.1.10 `
  --advertise 192.168.1.10 `
  --client-dir C:\Games\KartRider_5136 `
  --allow-remote-profile-creation
```

접속기만 실행하는 예:

```powershell
p5136.exe connect `
  --game-dir C:\Games\KartRider_5136 `
  --username player1 `
  --server 192.168.1.10
```

옵저버 계정은 `--observer`, 익명 리그 계정은 `--anonymous-league`를 추가합니다. 두 옵션은 동시에 사용할 수 없습니다.
안전 판정된 차단 트랙과 TF 트랙을 표시하려면 `--unlock-special-tracks`를 추가합니다.

Sikarugir wrapper를 사용하는 macOS 예:

```bash
p5136 connect \
  --game-dir "/Users/player/Games/KartRider_5136" \
  --username player \
  --server 192.168.1.10 \
  --runner sikarugir \
  --sikarugir-app "/Users/player/Applications/Sikarugir/kartrider.app"
```

`p5136.exe --help`, `p5136.exe server --help`, `p5136.exe connect --help`에서 전체 옵션을 확인할 수 있습니다.

## 로그와 문제 확인

모든 실행은 실행 파일 옆 `logs` 폴더에 새 로그를 만듭니다.

```text
logs/p5136-<timestamp>-<pid>.log
```

GUI 상단에도 현재 로그의 절대 경로가 표시됩니다. 서버가 받은 패킷과 보낸 패킷은 기본 파일 로그에 남습니다. 알 수 없는 패킷은 전체 제한형 원문을 기록한 뒤 응답 없이 소비하므로 선택 기능 하나가 전체 로그인 세션을 끊지 않습니다.

클라이언트 크래시를 조사할 때는 서버 로그와 클라이언트의 `logs` 폴더를 함께 보관하세요.

## 안전성과 라이선스

워크스페이스는 `unsafe_code = "forbid"`를 적용합니다. 외부 파일은 크기·개수·깊이 제한을 둔 읽기 전용 파서로 처리하고, 프로필 저장은 임시 파일과 원자적 교체를 사용합니다.

라이선스는 `AFL-3.0`입니다.
